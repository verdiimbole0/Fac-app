# Annexe 4 : Fiche de cadrage d'un projet IA

*ASBL augmentée : © 2026 Verdi Imbole. Reproduction autorisée pour l'usage interne de l'organisation de l'acheteur.*

## Objectif

Décrire un cas d'usage de façon homogène avant décision (porte 1).

## Mode d'emploi

1. Une fiche par cas d'usage ; deux pages maximum.
2. Utilisez la fiche prompt P6.1 pour un premier jet, puis complétez avec des faits.

## Champs de la fiche

| Rubrique | Contenu |
|---|---|
| Intitulé du cas d'usage | |
| Porteur (fonction) | |
| Problème (gabarit : pour [acteur], dans [processus], le problème est…, ce qui entraîne…) | |
| Valeur de départ mesurée | |
| Résultat attendu et indicateurs (cible, échéance) | |
| Solution sans IA envisagée | |
| Solution avec IA : niveau, rôle de l'IA / du logiciel / de l'humain | |
| Données nécessaires et classification (vert / orange / rouge) | |
| Personnes affectées et impact d'une erreur | |
| Contrôles humains indispensables | |
| Risques principaux et mesures | |
| Coûts sur 3 ans (postes) | |
| Questions à trancher | |
| Décision (go / no-go), date, décideur | |

## Exemple (extrait)

Problème : pour la secrétaire bénévole du CA, dans le processus de suivi des réunions, les PV sont diffusés en moyenne 30 jours après la réunion et 5 décisions sur 12 n'ont pas de responsable, ce qui entraîne des décisions non exécutées. Résultat attendu : projet de PV diffusé en 7 jours ; 100 % des décisions avec responsable et échéance.
